## Your five families



Keep the families distinct through their **design grammar**, not merely colors or fonts.



```
| Family                     | Primary buyer need           | Visual grammar                                     | Best work                                      |
| -------------------------- | ---------------------------- | -------------------------------------------------- | ---------------------------------------------- |
| **Micro Products**         | Buy/download quickly         | Bold type, short sections, decisive CTA            | Templates, tools, kits, mini-products          |
| **Industry & Hospitality** | Trust, atmosphere, booking   | Editorial grid, serif support type, photography    | Restaurants, clinics, gyms, services           |
| **Data Dashboards**        | Monitor and decide           | Dense panels, mono type, tables, status colors     | Analytics, inventory, internal tools           |
| **SaaS Products**          | Understand and trial         | Product UI, clear hierarchy, feature proof         | SaaS marketing, portals, booking tools         |
| **Enterprise Platforms**   | Evaluate risk and capability | Structured navigation, evidence, permissions, KPIs | B2B platforms, marketplaces, multi-tenant apps |
```



**Consumer Goods Catalog** should become a sixth family, not an awkward variation of SaaS or hospitality:



- Product-first photography and short benefit-led copy.

- Fast retail purchase and a clearly separate wholesale path.

- Trust modules: delivery estimate, returns, materials, reviews, payment methods, order tracking.

- Optional fulfillment story: order → confirmation → packing → dispatch → delivery.

- Product listing, product detail, cart, checkout, wholesale quote, and tracking are mandatory system modules.



## Tier separation



A tier must differ in **scope, ownership, proof, integration, and QA**—not only in “more animations.”



```
| Tier                     | Customer receives                                                                                                                                         | Limits                                                            |
| ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| **Low / Starter**        | One proven layout, one visual theme, 4–6 modules, mobile-ready, content swap, basic SEO                                                                   | No custom flow, no complex integrations, no bespoke motion        |
| **Mid / Growth**         | Chosen family template, 6–10 modules, CMS content, conversion sections, 1–2 integrations, custom theme                                                    | Limited custom components and predefined interactions             |
| **High / Professional**  | Custom module composition, tailored user flow, commerce or booking integration, analytics, motion direction, QA                                           | Uses your system; only selected components are built from scratch |
| **Premium / Enterprise** | Bespoke strategy, brand direction, original component work, advanced integrations, dashboards/roles, performance and accessibility audit, ongoing support | Quote-led; no artificial fixed scope                              |
```



For example, a **Starter consumer-goods store** gets catalog, product page, cart, FAQ, delivery/returns, and contact. A **Growth store** adds reviews, bundles, basic wholesale inquiry, and tracking. A **Professional store** adds supplier/order workflow, wholesale price logic, fulfillment storytelling, and a custom buyer journey. **Enterprise** adds multi-region inventory, roles, supplier portal, ERP/warehouse connections, audit trails, and a true design-system handoff.



## The shared design system



Build this before producing more templates:



```txt

packages/

tokens/ color, type, space, radii, shadows, motion

ui/ buttons, forms, cards, modals, navigation

commerce/ product, price, cart, shipping, tracking, quote

patterns/ heroes, grids, proof, pricing, comparison, dashboards

engine/ themes, layouts, modules, analytics, experiments

schemas/ template, tenant, page, module, product definitions

content/ CMS adapters, copy blocks, image/video rules

```



Use design tokens so each family can have a different personality without changing component code:



```ts

type Theme = {

color: Record<string, string>;

typography: Record<string, string>;

spacing: Record<string, string>;

radius: "none" | "small" | "medium" | "large";

motion: "minimal" | "standard" | "cinematic";

density: "airy" | "balanced" | "dense";

};

```



Example: Data Dashboards use zero/small radius, high density, and low motion. Hospitality uses generous spacing, restrained editorial motion, and image-led layouts. Consumer Goods uses clear price hierarchy, tactile media, and fast add-to-cart states.



## Tools and standards



A strong practical stack:



- **Figma** for token library, component variants, page compositions, and developer inspection.

- **Next.js + TypeScript** for storefronts and application shells.

- **Tailwind CSS plus CSS variables** for token-based styling and reliable theme switching.

- **Storybook** as the living component catalog: every button, card, order-status state, product state, and error state gets a documented story. It can render isolated components, simulate interaction, and validate their state changes. [storybook.js](https://storybook.js.org/docs/8/writing-tests/component-testing)

- **GSAP or Framer Motion** only for progressive enhancement—not required functionality.

- **Sanity, Payload, or Shopify** depending on whether content-first, custom commerce, or product-commerce speed is the priority.

- **Stripe / Shopify checkout** for secure payments instead of building payment infrastructure prematurely.

- **PostHog or Plausible** for funnel events: product view, add-to-cart, wholesale lead, checkout start, purchase, tracking lookup.

- **Playwright** for purchase-flow and visual regression tests; it can compare screenshots against approved baseline snapshots. [playwright](https://playwright.dev/docs/test-snapshots)



Set **WCAG 2.2 AA** as the baseline quality bar. Accessibility is testable and requires all applicable A and AA criteria, not only automated checks. Every cinematic template also needs a reduced-motion mode, accessible keyboard behavior, text alternatives, sufficient contrast, and a non-animated path to every important action. [w3](https://www.w3.org/TR/WCAG22/)

**Plan: Agency OS — A Unified Template Operating System (Proof of Concept)**

**1. Database Backbone — The "OS" That Makes the System Self-Documenting**

This is the core of your "creating itself database" goal. Every family, tier, module, token, template, and client project becomes a row the platform can read, render, and reuse.

- Create a `families` table holding the six design families (Micro Products, Industry & Hospitality, Data Dashboards, SaaS Products, Enterprise Platforms, Consumer Goods Catalog) with their visual grammar, primary buyer need, and best-work categories.
- Create a `tiers` table for the four tiers (Starter, Growth, Professional, Enterprise) storing scope, included modules, excluded modules, integration limits, and delivery checklist.
- Create a `modules` library table (the 25 core modules: navigation, hero, CTA, cards, pricing, product grid, product detail, cart, booking, quote request, reviews, FAQ, tracking, dashboard panels, tables, charts, auth, settings, empty/error/loading states) each tagged with the families and tiers it belongs to.
- Create a `templates` table for flagship templates and variants, linking to a family, a tier range, an included-module set, and a theme-token snapshot.
- Create a `theme_tokens` table storing the `Theme` shape (color, typography, spacing, radius, motion, density) so each family gets a distinct personality without touching component code.
- Create a `content_schema` table describing the editable fields per template (hero copy, product fields, FAQ entries, pricing rows) so non-technical staff can swap content per client.
- Create a `clients` + `projects` table pair so each prospect you pitch gets a project record linking a chosen template, tier, content overrides, and a live preview URL.
- Create a `qa_checklist` table recording the acceptance items per release (mobile, slow network, keyboard-only, reduced motion, broken image, empty catalog, out-of-stock, failed payment, failed tracking, visual regression).
- Lock every table with row-level security and grant access to the anon role for the public showcase, with an authenticated scope reserved for your agency staff area.

**2. Design Token & Theme System — One System, Six Personalities**

Build the shared foundation before producing templates, exactly as your `packages/` outline specifies, but condensed into this project.

- Define CSS custom-property tokens for color, typography scale, spacing, radii, shadows, and motion curves, exposed through Tailwind config.
- Implement the `Theme` type (color, typography, spacing, radius, motion minimal/standard/cinematic, density airy/balanced/dense) and a theme-provider that swaps token sets at runtime.
- Encode each family's character in a default theme: Data Dashboards = zero/small radius, dense, minimal motion; Hospitality = generous spacing, airy, restrained editorial motion, image-led; Consumer Goods = clear price hierarchy, tactile media, fast add-to-cart states; Micro Products = bold type, decisive CTA; SaaS = clear hierarchy, feature proof; Enterprise = structured navigation, KPI density.
- Add a reduced-motion mode and a high-contrast path as first-class tokens, not afterthoughts.
- Keep the palette away from the AI-default purple/indigo/pink gradient family; derive accent variants with `oklch()` from brand-supplied base colors.

**3. Core Module Library — 25 Reusable Building Blocks**

These are the Lego bricks every template assembles from. Each module is theme-aware and tier-aware.

- Build the universal modules first: navigation, hero, CTA, cards, pricing, FAQ, reviews, auth, settings, and the empty/error/loading states.
- Build the commerce modules: product grid, product detail, cart, checkout, shipping estimate, order tracking, wholesale quote request.

**4. Six Family Flagships — One Excellent Reference Per Family**

**5. Consumer Goods Flagship — The Sixth Family (your immediate first artifact)**

This becomes the first full vertical slice of the OS, end to end.

- Mandatory modules: product listing, product detail, cart, checkout, wholesale quote, order tracking, FAQ, delivery/returns, contact, reviews.
- Trust modules: delivery estimate, returns policy, materials, payment methods, verified reviews.
- Optional fulfillment story: order received → confirmation → packing → dispatch → delivery, surfaced as a tracking timeline.

**6. High-Value Interactive Structures — The Pitch-Worthy Showpieces**

**7. Tier Gating & Configurator — Sell Structured Packages, Not Custom Rebuilds**

**8. Integrations & The Free AI Production Stack**

**9. Quality Bar & Evidence Publishing — Trust Per Template**

- Set WCAG 2.2 AA as the baseline: keyboard-only paths, reduced-motion mode, text alternatives, sufficient contrast, and a non-animated path to every key action.
