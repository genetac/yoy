07 — The OS as its own database

Every flagship is a row.

The system documents itself. Schemas live in code, and every family, tier, module, template, project, and QA check becomes a queryable row in Supabase. The configurator reads from these tables to assemble new projects from existing modules.

7 tables — families, tiers, modules, templates, projects, tools, qa_releases
Row-level security — public read for showcase, authenticated write for staff
Versioned modules — AI agents can compose pages by selecting modules + applying a family theme
SELECT m.name, m.category, m.min_tier FROM modules m JOIN tiers t ON t.id = m.min_tier WHERE m.families && ARRAY['consumer-goods'] AND t.position <= 2 -- Growth or below ORDER BY m.category; -- 12 rows returned → these are the modules -- a Growth-tier consumer-goods client gets.

↑ The query the configurator runs when you pick "Consumer Goods / Growth" above.
